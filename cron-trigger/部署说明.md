# 24/7 定时触发（Cloudflare Worker + Cron Trigger）

## 为什么需要

GitHub Actions 的 `schedule` 是 best-effort，会被平台降频：实测最近三天线上部署间隔中位数 **约 4.8 小时**（配置写的是每 10 分钟），
而 `workflow_dispatch` 触发的运行会在几秒内开始执行（实测 26~30 秒跑完）。
抓取仍然由 GitHub 的机器做（它访问 B 站正常），所以这个方案**不依赖你的电脑开机**，也不需要 B 站对 Cloudflare 放行。

> 注意：Cloudflare Worker **不能**自己去抓 B 站——实测 B 站按 IP 段拦截 Cloudflare 出口（全部 HTTP 412）。
> 本 Worker 只做一件事：调 GitHub API 触发工作流。

## 部署步骤

### 1. 建细粒度令牌
1. 打开 <https://github.com/settings/personal-access-tokens/new>
2. Token name：`vr-psp-live-cron`；Expiration 自定（如 1 年）
3. Resource owner 选 `kaornao`；Repository access → **Only select repositories** → `vr-psp-live`
4. Permissions → Repository permissions → **Actions** 设为 **Read and write**（其余保持 No access）
5. Generate token，复制 `github_pat_...`（只显示一次）

### 2. 建 Worker
1. <https://dash.cloudflare.com> → **Workers & Pages** → **Create application** → **Start with Hello World!**
2. 名称填 `vr-psp-live-cron` → **Deploy**
3. 进去点 **Edit code**，清空模板，把本目录 `dispatch-worker.js` 整份粘贴 → **Deploy**

### 3. 配令牌与定时
1. 该 Worker → **Settings** → **Variables and Secrets** → Add：
   - 类型 **Secret**，名称 `GH_TOKEN`，值粘贴第 1 步的令牌
   - （可选）再加一个 Secret `RUN_KEY`，值随便设一个字符串，用于手动自检
2. 同页 **Triggers** → **Cron Triggers** → Add Cron Trigger，填 `*/10 * * * *` → 保存
3. 打开 `https://<你的worker地址>/` 应看到 `hasToken: true`；若配了 RUN_KEY，可访问
   `https://<你的worker地址>/run?key=<RUN_KEY>` 手动触发一次，返回 `{"ok":true,"status":204}` 即成功

## 自检

```powershell
gh run list --repo kaornao/vr-psp-live --workflow refresh-and-deploy.yml --limit 6
```

应能看到每 10 分钟一次、事件列显示 `workflow_dispatch` 的运行；线上 `status.json` 的 `updated_at` 也会保持新鲜。

## 备选：cron-job.org（不写代码）

不喜欢建 Worker 的话，用任意支持「POST + 自定义请求头」的免费定时服务，每 10 分钟请求：

- URL：`https://api.github.com/repos/kaornao/vr-psp-live/actions/workflows/refresh-and-deploy.yml/dispatches`
- 方法：`POST`
- 请求体：`{"ref":"main"}`
- 请求头：
  - `Authorization: Bearer <第 1 步的令牌>`
  - `Accept: application/vnd.github+json`
  - `Content-Type: application/json`

成功返回 **HTTP 204**。代价是令牌由第三方服务保存，所以更推荐上一种（令牌只存在你自己的 Cloudflare Secret 里）。

## 三层兜底

1. 本机每 10 分钟触发（电脑开机时）；
2. 本 Worker 的 Cron（全天候）；
3. GitHub 自己的 `schedule`（平台尽力而为，作为最后兜底）。
